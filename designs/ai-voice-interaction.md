# AI 语音助手交互与技术设计

> 状态：设计阶段 | `designs/core-pages.md` 的补充

## 第一部分：交互设计

### 目标

给 AI 语音助手增加两种自然交互：**语音唤醒**（任意成员用声音把 AI 请进对话）和**打断**（AI 说话时成员开口即可抢回说话权）。当前 AI 只能由房主按钮开关。

### 原则

- 状态全员可见（席位光环等视觉特效，不播放提示音）
- 输入有归属（唤醒和打断都明确谁在跟 AI 说话）
- 按钮关 = 真正关闭（不监听、不唤醒），不给"关了还在听"的错觉

### 状态机

```
  按钮开启           静默超时 / 休眠词
┌──────┐ ────► ┌──────┐ ─────────► ┌──────┐
│ 离线  │        │ 在线  │            │ 待机  │
└──────┘ ◄──── └──────┘ ◄───────── └──────┘
  按钮关闭            唤醒词
```

**迁移规则**：

| 迁移 | 触发 | 说明 |
|------|------|------|
| 离线 → 在线 | 房主按钮开 | 直达在线，不会只开到待机 |
| 在线 → 待机 | 静默超时（30~60 秒）/ 说休眠词 | 长时间无对话自动休眠，或主动说「小月再见」 |
| 待机 → 在线 | 任意成员说唤醒词 | 唤醒词只在待机生效；在线时说唤醒词当普通对话进 LLM |
| 在线/待机 → 离线 | 房主按钮关 | 任意时刻生效 |

**状态视觉表现**（状态不出现任何文字提示，纯特效区分）：

| 状态 | AI 席位特效 |
|------|------------|
| 离线 | 灰色 |
| 待机 | 微光，缓慢呼吸 |
| 在线 | 点亮，光环常亮 |

**在线内部子状态**（AI 醒着时的对话循环）：

| 子状态 | 含义 | AI 席位的对应特效 |
|--------|------|------------------|
| 聆听中 | 空闲，等下一句 | 光环常亮 |
| 接收中 | 正在听某人说完 | 光环微微呼吸 |
| 思考中 | LLM 生成中 | 光环转圈 |
| 说话中 | TTS 播放 | 说话波动 + 光环 |
| 被打断 | 刚被抢麦 | 光环急促闪烁 |

### 唤醒

- 固定唤醒词：「小月」（含近音字"小岳 / 小悦 / 小玥 / 小越"），MVP 不支持自定义，改词需改代码/配置
- 仅在待机生效：待机时说唤醒词 → 转在线，AI 席位亮起在线光环，进入聆听中，且这句唤醒词本身不送 LLM
- 在线时说唤醒词 → 不触发唤醒，但作为普通对话送 LLM，AI 正常回复
- 离线时说唤醒词 → 无动作（按钮是总开关，AI 已关闭时不监听、不唤醒）
- 唤醒词不送 LLM 只发生在"待机命中、触发转在线"的那一次；在线状态下任何语音（含唤醒词）都进 LLM

### 休眠

- 固定休眠词：「小月再见」（含近音字"小月拜拜"），MVP 不支持自定义，改词需改代码/配置
- 仅在线生效：说休眠词 → 回待机，仍在监听唤醒词，随时可被再次唤醒
- 待机 / 离线时说休眠词 → 无动作（休眠词只在在线状态监听）
- 休眠 ≠ 关闭：回待机只是暂停对话，彻底关闭仍需房主按钮

### 打断

- **触发条件**：AI 说话中，任意成员成段开口（VAD 片段 + 持续 > 阈值）
- **触发后**：TTS 立即停、LLM 生成取消、被打断的半句不入上下文
- 打断者这句直接成为下一轮输入，AI 回答打断者
- 打断后无人接话 → 回聆听中

### 边界情况

- 静音成员无法用语音唤醒，按钮是兜底
- 房主交接：重置为离线
- 连续 2~3 次出错 → 回待机
- 待机时说休眠词 → 无动作（休眠词只在在线生效）

## 第二部分：技术方案

### 1. 方案总览

核心判断：**唤醒词匹配放在文本层，不做音频级关键词识别（KWS）**。ASR 已全程运行（`global.go` 已注明"因语音唤醒 ASR 不能停"），唤醒词识别直接复用 ASR 的文本输出，无需引入额外模型。

```
浏览器麦克风 ──► SFU ──► ASR（全程跑）──► getAsrRes() ──► 唤醒词网关 ──► LLM ──► TTS
```

唤醒词网关是唯一的改动落点，位于 `backend/sfu/sfu.go` 的 `getAsrRes()`（当前第 554 行起，已留 TODO）。

### 2. 唤醒词 / 休眠词匹配

#### 2.1 核心思路

ASR 的错字几乎都是同音/近音字（"小月"被听成"小岳""小悦""小玥""小越"），字形不同但读音一致。因此匹配锚点用**拼音**，不用字形。

#### 2.2 匹配流程

```
ASR 文本 ──► 转拼音 ──► 归一化 ──► 包含匹配等价集 ──► 命中？
```

1. **转拼音**：Go 端用 `github.com/mozillazg/go-pinyin`，无音调模式
2. **归一化**：去声调、去空格、去标点、转小写
3. **包含匹配**：归一化后的拼音串是否包含等价集里任意一条

#### 2.3 拼音等价集

唤醒词「小月」与休眠词「小月再见」各用一份等价集，匹配算法相同，生效状态不同（唤醒词只在待机，休眠词只在在线）。

唤醒词：

| 汉字 | 归一化拼音 |
|------|-----------|
| 小月 / 小岳 / 小悦 / 小玥 / 小越 | `xiaoyue` |
| 小月同学 | `xiaoyuetongxue` |

休眠词：

| 汉字 | 归一化拼音 |
|------|-----------|
| 小月再见 | `xiaoyuezaijian` |
| 小月拜拜 | `xiaoyuebaibai` |

等价集是白名单，可控、可解释、误触发低。第一版只用"包含匹配"，不做编辑距离（双音节短词上编辑距离阈值难调，易误命中）。实测漏唤醒/误触发后再考虑加编辑距离兜底。

> 实现注意：`go-pinyin` 对"月"的 ü 输出（`u` 还是 `v`）需在实现时统一确认，保证等价集与转换结果同风格。

### 3. AI 状态机改造

现状：`global.StartAiAssistant` 是全局 `atomic.Bool`，一个开关打天下，撑不起"离线/待机/在线"三态，也无法按房间隔离。改为 **per-room 状态机**。

#### 3.1 新增状态类型

```go
// AIState 表示单个房间内 AI 助手的顶层状态
type AIState int

const (
    AIOffline AIState = iota // 离线：ASR 结果直接丢弃，不监听不唤醒
    AIStandby                // 待机：ASR 结果只过唤醒词网关
    AIOnline                 // 在线：ASR 结果直接送 LLM，非空文本即打断信号
)
```

状态挂在 `Room` 结构上（`backend/room/model.go`），随房间生命周期，替代全局 bool。ASR 结果带 `room_id`，`getAsrRes()` 据此取对应房间状态。

#### 3.2 getAsrRes 分发逻辑

```go
for res := range asr_cli.GlobalRecognizer.AudioOut {
    room := 取房间(res.RoomId)
    switch room.AIState {
    case AIOffline:
        continue // 离线：丢弃
    case AIStandby:
        if !匹配唤醒词(res.Text) {
            continue // 待机：未命中唤醒词，丢弃
        }
        room.AIState = AIOnline // 命中：转在线
        continue // 唤醒词本身不送 LLM，等下一句才是输入
    case AIOnline:
        if 匹配休眠词(res.Text) {
            room.AIState = AIStandby // 休眠词：回待机，不送 LLM
            continue
        }
        // 其余非空文本都算打断+新输入（见第 4 节）
    }
    llm_cli.LLMServiceClient.In <- 组装LLMRequest(res)
}
```

### 4. 打断机制

协议基础已具备：`proto/llm.proto` 的 `LLMRequest` 已有 `cancel = 7` 字段。

- **触发源**：ASR 中间结果（`text` 非空）即可判定"有成员开口"，不必等句尾 `is_final`——这样打断才即时
- **动作**：Online 状态收到新文本时，若当前有 LLM 生成进行中，先发 `cancel=true` 终止，再发新文本
- **即时性来源**：ASR 只收成员麦克风音频，AI 的 TTS 是输出轨不进 ASR，故"ASR 中间结果非空 = 有成员在说话 = 打断信号"成立
- **取消的链路**：`cancel=true` → Python Agent 的 `cancel_event` 置位 → 下一次 yield 前检测 → 终止生成（`agent/ARCHITECTURE_v1.md` 第 6 节已设计）
- **一致性**：被打断的半句回复不入历史，打断者那句保留

### 5. 信令变更

前端 `ai_status` 目前只回传 `Enable bool`，需扩展为三态，让前端能展示离线/待机/在线三种光环。

```go
// AiToggleRes 服务端回复客户端当前 AI 状态
type AiToggleRes struct {
    State string `json:"state"` // "offline" | "standby" | "online"
}
```

对应前端 `signaling.ts` 的 `AIStatusPayload` 和 `useVoiceRoom.ts` 的 `isAIEnabled`（bool）也要改。
