# eChat 核心页面产品文档

本文档描述第一阶段核心页面的产品逻辑，用于指导前端实现和后续 AI 接手。对应设计稿：

- `designs/core-pages-design.html`

## 页面范围

第一阶段包含 3 个页面和 2 个弹窗：

- 首页 / 进入页
- 声聊间页
- 离开 / 结束页
- 设置弹窗
- 邀请弹窗

页面复杂度保持轻量，但每个页面需要完整、可用、好看，不能像临时 demo。

## 命名

核心房间名称使用“声聊间”。

- 用户看到：声聊间、房间、成员、连麦、声音流畅。
- 避免在用户界面里使用：语音房、WebRTC、信令、ICE、SDP、ping/pong。

“声聊间”比“语音房”更轻一点，也更适合年轻社交场景。

## 首页 / 进入页

### 页面目标

让用户快速创建或加入声聊间。

### 用户路径

1. 用户打开首页。
2. 输入昵称。
3. 输入房间号，或点击创建房间。
4. 页面请求麦克风权限。
5. 成功后进入声聊间页。

### 页面模块

- 顶部品牌区：展示 `eChat` 和简短产品定位。
- 主文案区：表达“朋友进来后即可开麦聊天”的核心体验。
- 特性区：多人席位、打开就聊、一键邀请。
- 进入表单：昵称、房间号、创建房间、加入房间。
- 权限提示：提醒加入前需要允许麦克风。

### 按钮逻辑

- 创建房间：
  - 如果昵称为空，提示用户输入昵称。
  - 如果麦克风不可用，提示用户检查麦克风。
  - 成功后生成或使用后端返回的房间号，并进入声聊间页。

- 加入房间：
  - 如果昵称为空，提示用户输入昵称。
  - 如果房间号为空，提示用户输入房间号。
  - 如果麦克风不可用，提示用户检查麦克风。
  - 成功后进入对应声聊间页。

- 设备检测：
  - 打开设置弹窗或设备检测面板。
  - 用于提前确认麦克风和扬声器。

- 帮助：
  - 后续可打开帮助弹窗。
  - 第一阶段可以先保留入口或隐藏。

## 声聊间页

### 页面目标

承载多人实时声聊体验，让用户清楚看到谁在房间、谁在说话、自己是否静音、房间是否可正常通话。

### 页面模块

- 顶部房间栏：
  - 房间名。
  - 房间号。
  - 在线人数。
  - 房主。
  - 连接状态。
  - 邀请按钮。

- 成员席位：
  - 用户头像。
  - 昵称。
  - 房主标识。
  - 麦克风状态。
  - 正在说话状态。
  - 空席位和邀请入口。

- 成员列表：
  - 展示在线成员。
  - 展示房主、正在说话、已静音等状态。
  - 桌面端放右侧，手机端适合放到底部抽屉。

- 房间动态：
  - 用户加入。
  - 用户离开。
  - 已连麦。
  - 正在说话人数。
  - 正在重新连接。

- 底部控制栏：
  - 麦克风。
  - 扬声器。
  - 成员。
  - 邀请。
  - 设置。
  - 离开。

### 底部按钮逻辑

- 麦克风：
  - 开启时：本地音轨发送声音。
  - 关闭时：本地音轨静音，其他人听不到自己。
  - UI 状态需要明确区分“可说话”和“已静音”。

- 扬声器：
  - 开启时：播放远端成员声音。
  - 关闭时：暂停或静音远端播放。
  - 不影响自己是否把声音发给别人。

- 成员：
  - 桌面端：聚焦或展开右侧成员列表。
  - 手机端：打开成员底部抽屉。
  - 后续可扩展成员管理操作。

- 邀请：
  - 打开邀请弹窗。
  - 展示房间链接和房间号。
  - 支持复制链接。

- 设置：
  - 打开设置弹窗。
  - 可选择麦克风、扬声器。
  - 可切换降噪、自动增益。
  - 可测试麦克风。

- 离开：
  - 关闭本地麦克风音轨。
  - 关闭声聊连接。
  - 关闭或释放房间相关连接。
  - 跳转到离开 / 结束页。

## 声聊间状态

### 用户可见状态

用户界面只展示自然语言状态。

- 连接成功。
- 声音流畅。
- 正在重新连接。
- 已连麦。
- 正在说话。
- 已静音。
- 在线。
- 已离开。

### 状态映射

连接成功：

- 信令连接可用。
- 至少一个声聊连接已经建立，或当前用户已成功进入房间并可等待其他成员加入。
- 页面可以正常发送和接收房间事件。

声音流畅：

- 当前连接处于可用状态。
- 没有明显的播放失败、持续重连或长时间无远端声音问题。
- 后续如果接入质量指标，可结合丢包、抖动、音频能量、连接状态综合判断。

正在重新连接：

- 房间连接或声聊连接短暂断开。
- 前端正在尝试恢复。
- 此时不要立即让用户离开，应给出温和提示。

已连麦：

- 用户已进入房间。
- 本地麦克风已准备好。
- 声聊连接已可用，或者正在等待其他成员。

正在说话：

- 当前成员音频能量超过阈值。
- UI 使用绿色光环或标签提示。

已静音：

- 当前成员关闭了麦克风。
- UI 使用红色或弱化的麦克风标识。

## 离开 / 结束页

### 页面目标

给离开动作明确收尾，让用户知道自己已经退出，麦克风和连接已经关闭。

### 页面模块

- 离开确认文案。
- 本次房间摘要。
- 重新加入按钮。
- 回到首页按钮。

### 按钮逻辑

- 重新加入：
  - 带着原房间号回到加入流程。
  - 需要重新确认麦克风状态。

- 回到首页：
  - 清空当前房间状态。
  - 返回首页。

## 设置弹窗

### 弹窗目标

让用户调整声音输入和输出，不打断当前房间。

### 控件逻辑

- 麦克风选择：
  - 展示可用输入设备。
  - 切换后更新本地音轨。

- 扬声器选择：
  - 展示可用输出设备。
  - 浏览器不支持输出设备选择时，需要隐藏或置灰。

- 降噪：
  - 开启后降低环境噪声。
  - 第一阶段可以使用浏览器音频约束或先只做 UI 状态。

- 自动增益：
  - 自动平衡输入音量。
  - 第一阶段可以使用浏览器音频约束或先只做 UI 状态。

- 测试麦克风：
  - 检测麦克风是否可采集。
  - 可显示音量条或简单成功提示。

## 邀请弹窗

### 弹窗目标

让用户快速把声聊间分享给朋友。

### 模块逻辑

- 房间链接：
  - 主要分享内容。
  - 点击复制后给出“已复制”反馈。

- 房间号：
  - 用于口头告知或手动输入。

- 当前人数：
  - 让用户知道房间是否已经有人。

- 加入提示：
  - 告诉邀请者，好友进入后会看到麦克风授权提示。

## 文案原则

页面文案要像真实产品，而不是设计说明。

可以出现在用户界面：

- 隔着屏幕，也能听见彼此。
- 给朋友留一间有声音的小房间。
- 连接成功。
- 声音流畅。
- 正在重新连接。
- 已连麦。
- 准备好麦克风。

不应该出现在用户界面：

- 技术探索。
- 保留技术扩展空间。
- 主流程保持简单。
- WebRTC 稳定。
- 信令心跳正常。
- 手机访问请使用 HTTPS。

如果这些内容有必要说明，应放在产品文档、设计说明、帮助文档或技术日志中。
