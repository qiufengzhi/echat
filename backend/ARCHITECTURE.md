## 设计要点

1. **信令透传** — 后端不解析 WebRTC 内容，`Payload` 用 `json.RawMessage` 原样转发
2. **并发安全** — 读写分离 `sync.RWMutex`，双重检查锁，`sync.Once` 防重复清理
3. **双协程模型** — 每个客户端一个读协程 + 一个写协程（gorilla/websocket 不支持并发写）
4. **非阻塞发送** — `sendRaw` 使用 `select + default`，慢客户端直接丢消息不阻塞整个房间
5. **后台兜底清理** — 定时清理空房间，防止内存泄漏

## 房间与用户状态

> 当前代码没有定义显式状态枚举，状态通过房间内客户端数量和 `Client.RoomID` 隐式体现。

### 房间状态

| 状态 | 说明 | 判定条件 | 触发时机 |
|------|------|----------|----------|
| **空房间 (Empty)** | 房间存在但没有任何用户 | `len(r.Clients) == 0` | 最后一人离开 / 尚未有人加入 |
| **等待中 (Waiting)** | 仅 1 人，等待第二人加入 | `userCount == 1` | 第一个用户发送 `join` |
| **就绪 (Ready)** | 2 人及以上，可开始 WebRTC 协商 | `userCount >= 2` | 第二人及后续用户加入 |
| **已销毁** | 从 `allActiveRooms` 中移除 | map 中不存在 | 最后一人离开或 `cleanupIdleRooms` 兜底清理 |

```
状态流转:
  创建 → 等待中 (1人) → 就绪 (≥2人)
      ↓                    ↓
    已销毁 ←←←←←←←←←←←← 已销毁 (最后一人离开)
```

### 用户（Client）状态

| 状态 | 说明 | 判定条件 | 服务端发给客户端 |
|------|------|----------|-----------------|
| **已连接未入房** | WebSocket 已建立，尚未加入任何房间 | `client.RoomID == ""` | — |
| **在房等待** | 已加入房间，但只有自己 | `userCount == 1` | `waiting` |
| **在房就绪** | 已加入房间，有其他同伴 | `userCount >= 2` | `room_ready` + `user_joined`（广播给同伴） |
| **已断连** | 连接关闭，已从房间和全局列表移除 | `allConnectedClients` 中无此 ID | `user_left`（广播给剩余成员） |

```
状态流转:
  连接建立 → 已连接未入房
                │ join
                ▼
           在房等待 ──(第2人加入)──► 在房就绪
                │                       │
                │       leave / 断连     │
                ▼                       ▼
           已断连 ◄──────────────── 已断连
```

### 状态转换与信令消息对应

| 当前状态 | 事件 | 新状态 | 服务端消息 |
|---------|------|--------|-----------|
| 已连接未入房 | 收到 `join`（第1人） | 在房等待 | `waiting` |
| 在房等待 | 第2人 `join` | 在房就绪 | `user_joined`（给第1人）+ `room_ready`（给第2人） |
| 在房等待/在房就绪 | 收到 `leave` 或断连 | 已断连 | `user_left`（广播给剩余成员） |
| 在房就绪（最后1人离开） | 房间无人 | 房间已销毁 | — |
